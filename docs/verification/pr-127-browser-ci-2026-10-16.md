# PR 127 browser CI follow-up

## Failures and fixes

- Both CI browsers failed the appearance/search scenario because the page-wide
  `getByRole('option').first()` selected the underlying native language selector's
  Turkish option, not the search overlay. The artifact showed actual search results
  already present. The same failure was reproduced locally before editing.
  Scope the input and a specific movie-result assertion to the named search dialog.
- Chromium queue tests failed waiting/clicking Pause; the mobile playlist-search
  case also failed once before passing its retry. These actions raced the real
  four-second AAC fixture ending on a slower runner. The failure snapshots showed
  Play rather than Pause. Generate 90 seconds of real AAC instead, longer than
  these tests' 30-second budget, and keep file/Drive/track durations aligned.
- Update the timer test comment to describe the fixture without its obsolete
  four-second duration. Its active-audio, repeat-one and both-slot pause checks
  remain intact.

Only E2E fixture/selector code changed. No production code, API, schema, dependency
or migration changes. No tests skipped, assertions removed, retry counts changed
or timeouts increased. Fixtures remain real playable media in the disposable E2E
catalogue; no live account/provider/library was used.

## Verification

- Before the fix: focused Chromium mobile-drawer/search scenario failed at the
  expected selector assertion.
- After the fix: `pnpm exec playwright test` — **82 passed** across Chromium and
  WebKit, all files, no retries (11.8 minutes).
- `pnpm --filter @cinedrive/web test --maxWorkers=1` — **248 passed / 41 files**.
- `pnpm typecheck`, `pnpm lint`, `pnpm build` (including bundle budget),
  `pnpm docs:check`, formatting and whitespace checks passed.

GitHub's subsequent run is the authoritative CI result; local browser success
alone is not presented as proof that remote checks completed. No merge or
production deployment is performed as part of this fix.
